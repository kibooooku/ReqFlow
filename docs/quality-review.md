# ReqFlow 代码质量与缺陷分析

审查对象是本次实际生成的系统源码。初版已冻结于 `evidence/initial/source.zip`，包含界面与审查用例的修改前完整快照为 `evidence/before-redesign/source.zip`。问题没有人为注入；先记录失败证据，再实施受控修复。

## 实际发现及原因

| 编号 | 问题与真实触发 | 原因 | 重设计与验收 |
|---|---|---|---|
| Q01 | 仅选REQ-001建基线，未变更时比较返回5行，其中其他既有批准需求被标为新增 | 未区分项目全量和手工选定集合 | 基线持久化scope；selected仅比较原集合，project额外识别后来批准的需求；两类回归各自验证 |
| Q02 | 验证项PATCH接口拒绝expected_revision，无法表达并发编辑条件 | 需求有版本锁但验证项没有 | artifacts增加revision，PATCH要求expected_revision并在事务内比较；同一旧版本第二次更新409 |
| Q03 | 仪表盘读取中插入一条需求，total=9而coverage.total=10 | 多个SELECT各自读取不同时间点 | 复合读通过consistent_read复用同一WAL快照；用可控交错写入验证一致性 |
| Q04 | 创建文档在写事务开始前已将分析员降级为观察员，接口仍201 | 项目权限检查在事务外，检查与写入之间有时间窗口 | 将权限检查移入BEGIN IMMEDIATE事务；相同交错降权后403且无文档写入 |
| Q05 | 合法会话带非ASCII CSRF头字节FF得到500 | hmac.compare_digest的str输入要求ASCII，未校验异常header | 先检查ASCII与最大长度，再常量时间比较；无效输入403且正常会话保持有效 |
| Q06 | 创建前后带空格密码后，删除空格的不同密码也登录成功 | 请求基类str_strip_whitespace误用于凭据 | 密码类型显式关闭strip，其余文本仍清理空白；原密码200、改变后的密码401 |
| Q07 | 20个64KiB请求块全部读入后才返回413 | 完整await body后才检查256KiB限额 | 按流逐块计量，跨限即停止；20块测试最多消费5块，合法请求体重放给路由 |
| Q08 | 浏览器同时请求文档、成员和需求时500；并发测试触发sqlite3.ProgrammingError | sqlite默认线程亲和，而FastAPI同步依赖和路由可能落在不同工作线程 | 请求独立连接设置check_same_thread=False，继续保留事务；跨工作线程生命周期与16次并行认证读取均测试 |
| Q09 | 全新虚拟环境的缺包探测导致Windows PowerShell 5.1提前退出，未进入安装分支 | ErrorActionPreference=Stop将Python导入错误的stderr转为NativeCommandError | 用importlib.util.find_spec静默探测，退出码控制依赖安装；对缺包与已安装两种分支进行独立启动检查 |

Q04-Q07为研究代理独立审查未由其编写的main/schemas模块并复现，具体步骤在 `independent-review.md`。Q01-Q03由主控审查业务层并写回归测试。Q08由浏览器代理发现，主控根据服务器真实栈确认并补充并发回归。Q04/Q05/Q06/Q07涉及授权、凭据或输入安全边界；其余为功能、并发与可靠性缺陷。没有把这些称为已经被外部攻击者利用的漏洞。

## 证据及测试修正

初版44个用例实际40通过、4失败（170.99秒），其中3个失败对应Q01-Q03，另1个是测试数据错误：自审批测试提出的变更与当前内容完全相同，系统正确拒绝422，尚未进入审批分支。修正为真实不同标题后才能验证禁止自审，不能把这项计为系统缺陷。

冻结源码回放另复现Q04-Q07四项失败（4 tests / 4 failures / 0 errors），证据为 `evidence/initial/independent-review.xml`。Q08修复前两个并发用例失败，证据为 `evidence/initial/concurrency.xml`。这些批次使用不同测试集合，不直接以通过率相减声称质量提升。

首次测试因Windows沙箱临时目录与事件循环启动限制未执行到业务断言，保留environment-*文件。使用可写目录和允许本机事件循环的执行环境后获得上述正式结果。第一轮浏览器HTTP500属于Q08，第二轮异步弹窗等待不足是测试脚本同步问题；均保留ui-attempt证据。

## 受控代码结构

HTTP适配、业务服务、存储、安全原语和请求schema分开。所有需求写操作在同一事务内重检项目角色、状态和版本；版本、基线和审计表通过数据库触发器禁止UPDATE/DELETE。服务函数只使用参数化SQL，动态列名来自固定常量，拒绝任意字段。界面只能通过API改变状态；前端按钮隐藏不能代替后端授权。

重设计同时修改了schema、业务事务、前端契约与测试：验证项版本号必须从服务器获取；基线范围作为持久化语义；复合查询采用可重入读取快照；请求体上限从事后长度检查改为实际流量消费边界。数据库采用只增加字段的迁移，不重写历史快照。

## 质量结论的边界

最终API与业务回归共50项全部通过，耗时188.97秒；Python语句覆盖861/914，即94.20%。真实Edge界面验收16项通过，浏览器控制台与API错误均为0。Q09在交付阶段额外发现，属于启动脚本问题，其独立分支验证与50项API回归分别记录，不将其算入API用例数量。

覆盖率仅描述本测试套件实际执行的Python语句范围，不证明不存在漏洞。现有实现适用于本机教学演示；未实施公网压测、渗透测试或生产SSO。SQLite写事务串行化适合这个规模，不宣称高并发集群能力。审计触发器保护应用操作中的历史，不能防止拥有数据库文件写权限的系统管理员替换整个文件。

官方依据：FastAPI文档说明单个请求可能经过多个线程，SQLite配置与每请求会话必须配合使用：<https://fastapi.tiangolo.com/tutorial/sql-databases/>。本项目采用每请求独立sqlite3连接和显式事务，未使用全局共享连接。
